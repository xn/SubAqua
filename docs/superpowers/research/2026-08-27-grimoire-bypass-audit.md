What the engine already provides (so a bypass is measurable against it):

- `createOutfit()` (engine.ts:315-360) strips unowned `equip`/`avoid`/slot/familiar entries — a task never needs a `have()` gate in its spec.
- `customize()` (engine.ts:125-302) resolves `banish`/`killFree`/`freeRun`/`yellowRay`/`forceItems` against the ladders, pins the Peridot, pins **sea cowboy hat + sea chaps and injects a round-1 `tryItem(sea lasso)` starting macro** for every non-`freeaction` underwater task (engine.ts:144-148), and enforces player + familiar breathing.
- `dress()` (engine.ts:362-373) re-verifies `booleanModifier("Adventure Underwater")` and hard-equips a breather if the maximize missed.
- `prepare()` (engine.ts:304-313) does Fishy/Waterproofly upkeep on underwater non-free tasks; `post()` clears Beaten Up, poison, runs the dolphin whistle, diet, dreadscroll scan.
- Execution order is `createOutfit → customize → dress → prepare → do → post`, so **anything a `prepare` or `do` equips lands _after_ the maximizer has already run**.

## 4. Engine-level gaps that would let tasks be declarative

1. **Familiar-breather enforcement ignores the fielded familiar.** `engine.ts:293` reads `outfit.familiar` only, so a function-`do` task with a bare `Outfit` never gets a `das boot`/`bathysphere` — which is the entire reason `requiredFamiliarBreather()` exists and is hand-called at `mine.ts:79`, `gym.ts:56`, `colosseum.ts:109`, `skatepark.ts:113`. `customize()` already does the right thing 38 lines earlier for the `sea` keyword decision (`engine.ts:255`: `outfit.familiar ?? myFamiliar()`). Making :293 use the same expression deletes `mine.ts:78-81` outright and reduces the other three to belt-and-braces (they still need the `+equip` because their own `maximize` can swap the famslot).
2. **`adv1(loc, -1, filter)` bypasses the compiled CCS, so `customize()`'s combat work is silently dropped.** Every dynamic-fight task (`gym.ts:75`, `colosseum.ts:135`, `skatepark.ts:117`, `mine.ts:301`/`:353`, `yogurt.ts:345`, `shub.ts:101`, `finale.ts:93`) passes a non-empty filter, which makes mafia ignore `customize()`'s `startingMacro` — including the round-1 `tryItem(sea lasso)` at `engine.ts:145`. No filter in `fights.ts` re-adds it (`grep 'sea lasso' src/tasks` returns nothing). Either the engine should skip the lasso injection for filter-driven tasks (it is dead code there) or `fights.ts`'s filters should emit the lasso themselves on round 1.
3. **No way to say "this task dresses itself".** All of `gym.ts:36`, `skatepark.ts:69`, `colosseum.ts:73` are `underwater: true` wrapper tasks, so the engine builds an outfit, pushes `sea` (+`-tie`), runs a full `maximize` in `dress()`, verifies breathing — and the helper's own `maximize` throws all of it away one line later. A `selfDressing?: boolean` task field that short-circuits `createOutfit`/`customize`'s breathing block/`dress` would remove one maximize per turn on the three highest-turn-count Phase-4 tasks and remove the lasso-pin conflict in fix-now #4. (The inverse fix — giving those tasks a real delayed `outfit` and keeping only `adv1` in `do` — is cleaner but blocked by `burn.ts` calling the same helpers outside task machinery.)
4. **No outfit field for "un-wear this so a coinmaster can count it".** `gym.ts:94-95`, `school.ts:211-212`, `mine.ts:267-268`/`:317-318` all hand-unequip cost items. `avoid` is the near-miss: it emits `-equip X` into the maximizer string, which only helps when a maximize actually runs, and these are `freeaction` / non-adventuring branches. A `strip?: Item[]` field honored in `dress()` would cover all four sites.
