# `subaqua sim` audit — 2026-09-06

Why: `sim` is about to go to a wider audience. A green verdict that then aborts a run, or a
crash, costs goodwill. Four read-only subagent audits (abort sites vs `necessaryAt`, route
resources vs sim rows, pull list vs `pulls.ts`, runtime safety of `sim.ts` itself) were run
against main at `cde5560`; every finding below was spot-checked in the code before the rewrite.

## 2. `necessaryAt` false negatives (run aborts, sim said recommended/optional)

All confirmed against grimoire `checkLimits` (`engine.js:331-350`: a task still incomplete after
`limit.tries` **throws**).

| Row                                                                                  | Abort                                                                                                                | Tiers   |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ------- |
| a workshed                                                                           | `init.ts` "Workshed" `tries:1`, nothing to install → throw                                                           | all     |
| clan photobooth (Sheriff kit)                                                        | `init.ts` "Photobooth" `tries:2` / explicit abort on a non-Sheriff kit                                               | all     |
| unholy diver summon source                                                           | `summon.ts:86` abort; Diver Summon `ready` is true from run start (`helmet.ts:151`)                                  | low/mid |
| Black Crayon Golem summon source, when Just the Facts is known                       | `summon.ts:86`; Golem Recall `ready` = have(JtF) (`grandpa.ts:57`)                                                   | low/mid |
| sea cowboy summon source, when Sword of S Words + locket (+ no pay phone at low/mid) | `summon.ts:86`; Sword Imprint `ready` (`guild.ts:60-65`)                                                             | all     |
| Anemone Mine / Marinara Trench / Dive Bar unlocked                                   | Mine Teflon (`mine.ts:220`), `grandpaZone()` (`lib/index.ts:87-95`) by prime stat; the task stalls to its soft limit | all     |
| Leprecondo layout (when owned)                                                       | `init.ts` "Leprecondo" `tries:1` with <4 layout pieces discovered                                                    | all     |
| duplicate.edu (when a Source Terminal is installed)                                  | `daily.ts` "Terminal Educate" `tries:1`                                                                              | all     |

Not added as necessary, deliberately:

- **Unaccompanied Miner**: without it the run pulls a lodestone from the mall (`mine.ts:80-86`);
  the abort at `mine.ts:271` only fires if that pull also fails. Recommended, why text says so.
- **Water breathing at low tier**: the old row said "low tier must own one" but tested
  `haveAnywhere`, and low tier never pulled the tank (`policy.ts:26` allowDiscretionaryPulls=false,
  `init.ts` seaGearPulls via `discretionaryPull`). A low-tier player without an Asdon aborted at the
  first underwater lasso-training task (`engine.ts:391`): the trunks are `trainingBlockedGear`
  (`outfit.ts:73`) and the chaps take the pants slot, so only a SCUBA tank breathes under the
  hat + chaps. **Route fix**: `init.ts` now pulls the Elf Guard SCUBA tank with `pullSequence` at
  every tier when no SCUBA tank (`outfit.ts scubaTanks`) is owned. Row is recommended at all tiers.
- **sushi-rolling mat, little bitty bathysphere, swimming trunks**: rows dropped. The Old Man hands
  all three out at init (`docs/gold-star-run.txt:783-786`), so the old "necessary" mat row and the
  old breather rows were false reds for anyone who had not kept them.
- **buyLimit / storage meat**: `pulls.ts:37` aborts when a mall pull costs more than `buyLimit()`;
  a mall lookup per item is a server hit, so sim prints the limit and the storage meat instead.

## 3. Route fixes bundled (outside sim.ts)

- `init.ts`: SCUBA tank pull is unconditional when no SCUBA tank is owned (above).
- `pellet.ts`: Flytrap Imprint's `ready` now requires `selectFreeKill({dropsMatter:true})`, the
  same guard Sword Imprint has (`guild.ts:65`). Without it a `.killFree()` task with no free-kill
  source falls back to `MyActionDefaults.killFree()` = `Macro.abort()` (`combat.ts:54-62`). The
  Garden Pellet fallback is ready in the same case so the lane does not stall pelletless.
- `tier.ts`: `detectTier(owned = have || storage)`.
- `args.ts`: `command` has `setting: ""`.

## 5. Review corrections (second pass, subagent review of the diff)

- Photobooth: the Sheriff pieces are quest items and do not reach the run, so they only count in-run.
- Summon source via fax: `loungeHas("deluxe fax machine") && canFaxbot(monster)`, since the route's
  rung is `canFaxbot` (`summon.ts:71`).
- Map unlocks: Trench / Dive Bar are necessary only for the matching prime stat (in-run exact;
  pre-ascension the current prime stat stands in and the row says so). Red map rows carry the
  "visit place.php?whichplace=thesea and rerun" hint because mafia infers the prefs from that page.
- Terminal: an empty `sourceTerminalEducateKnown` prints "?" (unknown), not red.
- Closet pre-ascension counts as owned (ascension empties it into Hagnk's); in-run it needs
  autoSatisfyWithCloset.
- Sword Imprint row also requires a drop-safe free kill in-run (`guild.ts:65`).

## 6. Open items (not changed)

- `pulls.ts:54-58` reserves a pull slot for crayon shavings that nothing ever pulls.
- `saber.ts:32` `diverHuntActive()` tests `haveAnywhere(scubaTank)`; consistent now that the tank
  is pulled at init, but a stocked tank still switches the diver hunt off before the pull happens.
- The map-unlock rows mark Trench and Dive Bar necessary at every tier because the ascension
  class is unknown pre-ascension; only the prime-stat zone actually stalls.
- Skills that are not permable (mafia `Skill.permable=false`) are tested with `have()` even
  pre-ascension; if any route skill is granted per-run by an IotM this is right, if one is
  class-bought it will show ✓ and vanish.
